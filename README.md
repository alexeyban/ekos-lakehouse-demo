# ekos-lakehouse-demo

The project an [EKOS Lakehouse](https://github.com/alexeyban/ekos-lakehouse) demo produced: a
PostgreSQL database ([Pagila](https://github.com/devrimgunduz/pagila), the DVD-rental sample)
taken to Apache Iceberg tables, with the pipeline EKOS generated, its git history, the changes
made to the source during the demo, and the documentation generated from all of it.

Nothing here was written by hand except `ekos.toml`, `lakehouse-docs.toml` and the mart
descriptions in `marts/`. Everything else is output of `ekos-lakehouse` and `lakehouse-docs`,
committed as it was produced.

**Watch the run:** [the 14-minute demo video](https://youtu.be/EGpYzn_-fv4) — every step, from an
empty sandbox to the documentation in this repository.

**Start with the documentation:** the [wiki](https://github.com/alexeyban/ekos-lakehouse-demo/wiki)
— 63 pages with ER diagrams, column lineage, reconciliation results, health and the change log,
generated by `lakehouse-docs` and published with its GitHub wiki publisher (the sidebar keeps the
section hierarchy).

**dbt docs:** [alexeyban.github.io/ekos-lakehouse-demo](https://alexeyban.github.io/ekos-lakehouse-demo/)
— the dbt project's own site (models, columns with the warehouse's types, tests, compiled SQL,
lineage graph), from `dbt docs generate --static`, served by GitHub Pages from the `gh-pages`
branch.

Source changes applied during the demo, and what became of them (see `pipeline/` history):

1. `customer.loyalty_tier` added (new nullable column) → committed automatically
   (`lakehouse: apply 1 safe change(s)`).
2. `rental.rental_date` renamed to `rented_at` → proposed on a branch with its impact
   (`pipeline/proposals/bb155528506d.md`), approved by the merge
   `approve: rename rental.rental_date to rented_at`; bronze renamed the column in place.
3. A gold mart from a written description (`marts/rentals_by_store_month.md`) → proposed at the
   end of the demo ([pull request #1](https://github.com/alexeyban/ekos-lakehouse-demo/pull/1)),
   approved afterwards (`approve: gold mart rentals_by_store_month`).

## After the demo: gold marts

Three more marts were described, drafted, reviewed and approved (merge = approval), and the
pipeline was run with all four. Approving the first one exposed a bug: the generated Dagster job
never built gold models, and their reconciliation tests then failed the whole run (fixed in
[ekos-lakehouse#3](https://github.com/alexeyban/ekos-lakehouse/pull/3); the pipeline here was
re-rendered with `lakehouse generate --from-lock`).

| Mart | Grain | Measures | Rows | Reconciles to |
|---|---|---|---|---|
| `rentals_by_store_month` | store (of the rented copy), month | rentals | 104 | 51,805 rentals |
| `rentals_by_film_rating_month` | film rating, month | rentals, distinct customers | 260 | 51,805 rentals |
| `inventory_by_store_rating` | store, film rating | copies, distinct titles | 10 | 4,581 copies |
| `film_catalog_by_rating` | film rating | films, average rental rate, average length, total replacement cost | 5 | 1,000 films |

Every term resolved to a silver column with nothing invented; each mart has a grain-uniqueness
test and a measure-reconciliation test against silver, all passing.

## Layout

```
ekos.toml               the EKOS project: services, source, watermarks (names the password variable, never a password)
lakehouse-docs.toml     documentation settings: facts only; purpose, owners and SLAs are left as manual sections
marts/                  the gold mart descriptions, as their author wrote them
pipeline/               the pipeline repository ekos-lakehouse generates (imported with its history)
  lakehouse.lock.json     the deployed plan: every table's load mode with its evidence, the type mapping
  bronze/                 Trino SQL per table (create, load, deletes, schema, maintenance)
  dbt/                    silver models with generated tests; gold marts (arrived by approved proposals)
  dagster/                the generated Dagster project
  proposals/              approved proposals: the schema change and the four gold marts
docs/_evidence/         the JSON the wiki was generated from: status, tables, proposals, check, reconcile, dbt run results
```

## Reproduce

Needs the ekos-lakehouse sandbox (`docker compose -f deploy/docker-compose.lakehouse.yml up -d`
and `deploy/fixtures/pagila.sh` in the ekos-lakehouse repository), then from this directory:

```bash
export EKOS_LH_PG_PASSWORD=ekos-local-only      # the sandbox's local-only default
ekos-lakehouse init
ekos-lakehouse lakehouse doctor
ekos-lakehouse lakehouse plan
# regenerate the documentation (Python ≥ 3.11, see tools/lakehouse-docs in ekos-lakehouse)
PYTHONPATH=<ekos-lakehouse>/tools/lakehouse-docs python -m lakehouse_docs all --project . --out docs --check
# and publish it to the wiki (GITHUB_TOKEN with contents: write)
python <ekos-lakehouse>/tools/lakehouse-docs/publish/publish_github_wiki.py --docs docs --repo alexeyban/ekos-lakehouse-demo --prune
```

## What is not here, and one edit

- `.ekos/` (the project's local ledger) and `.dagster/` (the orchestrator's instance): local
  state, rebuilt by running the pipeline.
- `pipeline/dbt/target/` and the dbt `manifest.json` copied from it into `docs/_evidence/`:
  build artifacts; compiled dbt SQL can carry the masking key, so it is never committed.
- In `docs/_evidence/tables.json` and `docs/_evidence/run_results.json`, absolute paths of the
  pipeline on the machine that ran the demo were replaced with the relative `pipeline/…`.

Credentials in this repository are the sandbox's local-only defaults, documented as such in
ekos-lakehouse; nothing here connects to anything outside a local sandbox.
